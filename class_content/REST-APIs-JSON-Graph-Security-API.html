03 / 20  ·  Why it matters

REST APIs: the bedrock of the modern era

Every portal click, every AI prompt, every web app and every agent tool call is an HTTP request carrying JSON. Read one REST call and you can read them all.

01Cloud — ARM, Microsoft Graph, Defender, Sentinel: portals, CLIs, SDKs and IaC are all REST clients.
02GenAI — a prompt to Azure OpenAI or Foundry is a POST with a JSON body; the answer is JSON.
03Web applications — front ends talk to back ends, and services talk to each other, over REST.
04MCP — servers speak JSON (JSON-RPC 2.0); the tools they expose to agents are mostly wrappers over REST APIs.
05Security ops — Defender XDR alerts, incidents and hunting are exposed through the Graph Security API.
06Automation — PowerShell, Logic Apps, GitHub Actions, Terraform: same verbs, same status codes.
04 / 20  ·  Definitions

What the letters stand for

RESTREpresentational State Transfer
An architectural style, not a product. Resources are named by URIs, manipulated with standard HTTP verbs and exchanged as representations — almost always JSON. It is stateless: every request carries everything the server needs, including the access token.
APIApplication Programming Interface
A contract for software talking to software. It defines what you may ask for, how to ask, and exactly what comes back — so a script, a Logic App or an AI agent can call it without a human clicking through a portal.
JSONJavaScript Object Notation
The representation. The lightweight, human-readable text format that travels to the API in request bodies, through pipelines and agents, and from the API in every response — including errors.
05 / 20  ·  REST anatomy

Anatomy of a REST call

One request in, one response out — four parts each way.

The request
Method — the verb: GET read · POST create / run an action · PATCH update · DELETE remove
URI — the noun: https://graph.microsoft.com/v1.0/security/runHuntingQuery (host · version · resource path)
Headers — metadata: Authorization: Bearer <token> · Content-Type: application/json
Body — the JSON payload (only for POST / PATCH / PUT)
The response
Status code — 2xx success (200, 201, 202) · 4xx you (400, 401 no/invalid token, 403 missing permission, 429 throttled) · 5xx them
Headers — Content-Type · request-id (quote it in support cases) · Retry-After on 429
Body — the JSON representation of the result; errors are JSON too (error.code, error.message)
Stateless — no server-side session; the token is the state
06 / 20  ·  HTTP verbs

Five verbs do almost everything

Verb · Graph exampleWhat it means
GET — readGET /v1.0/security/alerts_v2
  • Returns a representation; nothing changes server-side. Safe, idempotent, no body — repeat it freely.
POST — create or actPOST /v1.0/security/runHuntingQuery
  • Creates a resource or runs an action with a body. runHuntingQuery is an action — that is why our call is a POST.
PATCH — updatePATCH /v1.0/security/incidents/{id}
  • Partial update: send only the changed properties, e.g. { "status": "resolved" }; everything else is left alone.
PUT — replacePUT /v1.0/me/drive/items/{id}/content
  • Create-or-replace the whole representation; idempotent. Rare in Graph outside content uploads.
DELETE — removeDELETE /v1.0/subscriptions/{id}
  • Idempotent, usually 204 No Content. Deleting twice is not an error in principle — the second call finds nothing.
07 / 20  ·  JSON

JSON: to, through and from every REST API

Why it matters
Text, not binary — human-readable, language-agnostic (RFC 8259). PowerShell, Python and browsers all parse it natively.
To the API — request bodies are JSON, declared with Content-Type: application/json.
Through the pipeline — Logic Apps, Sentinel playbooks, MCP tool calls and AI agents hand JSON from step to step.
From the API — every response is JSON, including errors (error.code, error.message).
JSON in PowerShell 7
Invoke-RestMethod deserializes JSON into [pscustomobject]; navigate with dot notation: $r.results[0].AccountUpn.
ConvertFrom-Json / ConvertTo-Json — text ↔ objects. Mind -Depth (default 2) or nested data is flattened.
Hashtable ↔ object — @{ Query = $kql } is the PowerShell shape of { "Query": "…" }.
Test-Json — validate a payload against a JSON Schema before you send it.
08 / 20  ·  JSON anatomy

Anatomy of a JSON object

One object, six data types, an array of objects (rows in a table) and an object within an object. Whitespace is irrelevant; keys are unique and case-sensitive; there are no comments and no trailing commas.
09 / 20  ·  Data types

Six JSON types → PowerShell 7

JSON · exampleRules → PowerShell 7 equivalent
string · "Adele Vance"
  • Double quotes only; escape \" \\ \n \uXXXX; dates are ISO 8601 strings → [string], cast [datetime]
number · 1042 87.5
  • No quotes, no leading zeros; one numeric type → [int] / [long] / [double] — the client picks the width
boolean · true false
  • Lowercase and unquoted — "true" is a string → $true / $false ([bool])
null · null
  • Explicitly "no value" — different from a missing key and from "" → $null
object · { "key": value }
  • Unordered key/value pairs; keys are unique quoted strings → [pscustomobject] (or -AsHashtable); build with @{ }
array · [ v1, v2 ]
  • Ordered, zero-based, mixed types allowed; an array of objects = a collection → [object[]], $r.results[0]

11 / 20  ·  Graph Security API

Advanced hunting through Microsoft Graph

01

The endpoint

  • POST /v1.0/security/runHuntingQuery
  • Graph Security API = one broker in front of Microsoft security providers; Defender XDR answers this call
  • Hunts across devices, identities, email and apps with KQL
  • Available in Global, US Gov L4 (GCC High) and L5 (DoD); not in China
  • Replaces the legacy api.security.microsoft.com hunting API (retirement began Jan 2026)
02

The request

  • Authorization: Bearer <token>
  • Content-Type: application/json — add ; charset=utf-8 for non-ANSI characters in KQL
  • Query (string, required) — the KQL
  • Timespan (optional, ISO 8601) — P1D, P30D, start/end; default 30 days; shorter of query filter vs Timespan wins
  • workspaceId (optional) — target a Sentinel workspace
03

Response & quotas

  • 200 OK → huntingQueryResults
  • schema[] — one object per column: name, type
  • results[] — one object per row
  • Hunting service quotas: 30-day lookback · up to 100,000 rows · at least 45 calls/min per tenant · 3-minute timeout
  • 429 = CPU quota reached — read the body, honor Retry-After
12 / 20  ·  Permissions

ThreatHunting.Read.All & admin consent

The permission
Display name — "Run hunting queries". The least-privileged permission for runHuntingQuery; there is no lower option.
Delegated (scope) — "on behalf of the signed-in user". The app can never see more than that user could in the portal.
Application (app role) — "without a signed-in user". For daemons, pipelines and scheduled automation.
Admin consent required: Yes — for both. A regular user cannot approve it; the sign-in prompt says "Need admin approval" until an admin consents.
Admin consent — purpose & mechanics
Purpose — the permission exposes tenant-wide security telemetry; a privileged human must review what an app gets before any token is issued.
Who — Privileged Role Administrator (any permission); Cloud Application / Application Administrator (all but Graph application roles).
How — App registrations → API permissions → Grant admin consent; the /adminconsent?client_id= URL; the prompt's "Consent on behalf of your organization"; or programmatically — POST …/appRoleAssignedTo.
Result — OAuth2PermissionGrant (delegated) or appRoleAssignment (application); the token then carries scp or roles = ThreatHunting.Read.All.
13 / 20  ·  OAuth 2.0

How the token flows

1
Register & consent — the setup script creates the app, consent, a secret, and a 12-month self-signed certificate named <app name> - TRAINING. Its TRAINING ONLY details correlate every app and tenant ID.
2
Request a token — POST the token_endpoint from the tenant's OpenID discovery document with client_id, client_secret (or certificate), scope=https://{msgraph_host}/.default, grant_type=client_credentials. Public or Azure Government — same code.
3
Receive JSON — access_token is a signed JWT (about an hour): app-only secret and certificate tokens carry roles; delegated carries scp. The script clears old token state, copies the complete JWT to the clipboard, and it decodes directly at jwt.ms.
4
Call Graph — Authorization: Bearer <token> + a JSON body → POST /v1.0/security/runHuntingQuery.
5
Graph validates signature, audience, expiry and the permission claim, runs the KQL, and answers 200 OK + huntingQueryResults. No token → 401; token without the claim → 403.
14 / 20  ·  The query

The hunting query (KQL)

SignIns-Last24h.kql
// Every user who signed in during the last 24 hours — one row per account
EntraIdSignInEvents // Defender XDR advanced hunting table (Entra ID P2)
| where Timestamp > ago(24h) // time filter — API Timespan also applies; shorter wins
| where ErrorCode == 0 // 0 = successful sign-in; anything else = failure code
| summarize LastSignIn = max(Timestamp),
SignInCount = count(),
Apps = make_set(Application, 5) // becomes a JSON array inside each result row
by AccountUpn, AccountDisplayName // one row per user
| order by LastSignIn desc
Runs unchanged in the Defender portal → Advanced hunting. Same text, same result — the API just lets a script ask the question. On October 19, 2026 the old AADSignInEventsBeta table is retired in favour of EntraIdSignInEvents.
15 / 20  ·  Step 1 of 3

Get a token — PowerShell 7

pwsh — Step 1 · Invoke-RestMethod → token endpoint
# OAuth 2.0 client-credentials flow — two REST calls to Entra ID before we touch Graph (no user involved)
$tenantId = '<tenant-id>'; $clientId = '<app-client-id>' # New-HuntingAppRegistration.ps1 → HuntingDemo.settings.json
$oidc = Invoke-RestMethod -Uri "https://login.microsoftonline.com/$tenantId/v2.0/.well-known/openid-configuration"
# ↑ GET (default verb), no token. JSON back: token_endpoint · msgraph_host = graph.microsoft.com | graph.microsoft.us
$secret = Read-Host 'Client secret' -AsSecureString # prompt for it — never hard-code secrets in a script
$form = @{ # hashtable → form-urlencoded body (the POST default)
client_id = $clientId
client_secret = ConvertFrom-SecureString $secret -AsPlainText # PS 7: decrypt only at the moment of use
scope = "https://$($oidc.msgraph_host)/.default" # '.default' = all app roles granted by admin consent
grant_type = 'client_credentials' # the app *is* the identity
}
$tok = Invoke-RestMethod -Method Post -Uri $oidc.token_endpoint -Body $form # → access_token · token_type · expires_in
$token = ConvertTo-SecureString $tok.access_token -AsPlainText -Force # -Token expects a SecureString
Discovery makes the cloud automatic. Run -AuthMode Certificate to replace the shared secret with the correlated training certificate; run -AuthMode Delegated for interactive user consent. Every mode copies the complete JWT to the clipboard.
16 / 20  ·  Step 2 of 3

Invoke-RestMethod, switch by switch

pwsh — Step 2 · POST /security/runHuntingQuery
$kql = Get-Content -Path .\SignIns-Last24h.kql -Raw # the query from slide 14, as one string
$call = @{
Method = 'Post' # HTTP verb — runHuntingQuery is an ACTION, so POST
Uri = "https://$($oidc.msgraph_host)/v1.0/security/runHuntingQuery" # host from discovery
Authentication = 'Bearer' # PS 6+: emits Authorization: Bearer <token> for you
Token = $token # SecureString from Step 1 (https required)
ContentType = 'application/json' # tells Graph how to parse the body (POST default is form)
Body = @{ Query = $kql; Timespan = 'P1D' } | ConvertTo-Json # hashtable → JSON text
StatusCodeVariable = 'status' # PS 7: capture 200 / 401 / 403 / 429 into $status
ResponseHeadersVariable = 'hdrs' # PS 6+: request-id, Retry-After, Content-Type → $hdrs
MaximumRetryCount = 2; RetryIntervalSec = 5 # retry transient failures — a 429 honors Retry-After
}
$response = Invoke-RestMethod @call # splatting: one hashtable carries every switch
The JSON response is deserialized automatically — $response.schema and $response.results are ready; no ConvertFrom-Json needed.
17 / 20  ·  Step 3 of 3

Read the response, write the JSON file

pwsh — Step 3 · huntingQueryResults → SignIns-Last24h.json
"HTTP $status · $($response.results.Count) rows · request-id $($hdrs['request-id'])" # status + headers we captured
 
$response.schema | Format-Table name, type # schema = ARRAY OF OBJECTS (column name + type)
$response.results | Select-Object -First 5 | # results = ARRAY OF OBJECTS (one per user)
Format-Table AccountUpn, LastSignIn, SignInCount, Apps # Apps = ARRAY inside each object
 
$path = ".\SignIns-Last24h-$(Get-Date -Format 'yyyyMMdd-HHmm').json"
$response | ConvertTo-Json -Depth 10 | # -Depth: default is 2 — nested arrays would be cut off
Set-Content -Path $path -Encoding utf8 # PS 7: utf8 = UTF-8 without BOM
 
(Get-Content $path -Raw | ConvertFrom-Json).results[0].AccountUpn # round-trip: text → objects → dot notation
The saved file is exactly slide 8: one object → @odata.context (string) + schema (array of objects) + results (array of objects, each with a nested Apps array).
18 / 20  ·  Reference

Invoke-RestMethod switches that matter

SwitchWhat it does · why you care
-Method
  • The HTTP verb (Get, Post, Patch, Put, Delete). Actions such as runHuntingQuery are POST even though they only read.
-Uri
  • Scheme + host + version + path. Take the host from the tenant's OpenID metadata (msgraph_host): graph.microsoft.com, graph.microsoft.us, dod-graph.microsoft.us.
-Authentication Bearer -Token
  • PS 6+. Builds Authorization: Bearer <jwt> from a SecureString; https only. Manual form: -Headers @{ Authorization = "Bearer $t" }.
-ContentType · -Body
  • Hashtable body → form pairs (token call); string body is sent verbatim, so ConvertTo-Json first and set application/json (Graph).
-StatusCodeVariable · -ResponseHeadersVariable
  • PS 7 / PS 6+. Capture the status code and the header dictionary (request-id, Retry-After) into named variables.
-MaximumRetryCount · -RetryIntervalSec · -SkipHttpErrorCheck
  • Retry on 400–599; a 429 honors Retry-After. -SkipHttpErrorCheck (PS 7) returns the JSON error body instead of throwing.

Prerequisites & Microsoft Learn

Before you run it
Licensing — Defender XDR; EntraIdSignInEvents needs Entra ID P2 (fallback: IdentityLogonEvents).
App registration — setup creates consent, a secret, and a 12-month cert named <app name> - TRAINING. .NET X509Store holds the non-exportable key; Entra receives the public key.
PowerShell 7.3+ — pwsh, check $PSVersionTable.PSVersion. Certificate naming uses the .NET 7 X.500 builder.
Cloud — endpoints are discovered from the tenant (Public → graph.microsoft.com, Azure Gov → graph.microsoft.us / dod-graph.microsoft.us); -Environment Public|AzureGov overrides.
